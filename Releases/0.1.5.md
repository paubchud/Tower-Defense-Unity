# Tower Defense 0.1.5 - Experimental Steam + EOS guest playtest

Download the Windows or macOS ZIP under Assets, **not** the source-code ZIP. Extract the whole package. Both players need **0.1.5** on separate devices. This prerelease is a networking prototype, not the completed tower-defense combat game or a production Steam release.

## Guest play: no Steam/Epic account screen

Launch **TowerDefense.exe** / **TowerDefense.app** directly, choose **Play as Guest**, wait for EOS sign-in, then Play and a class. One player chooses **Host Guest**, copies/shares the **full TDG code**, and the other chooses **Join Guest**. Both ready up. The host must stay open. EOS relay is requested so users should not need manual port forwarding; real separate-home/device reachability still needs testing.

Steam and guest matches are separate. Guests use real EOS Connect Device ID login, not their local profile GUID as a credential. Guest rooms are code-selected advertised EOS lobbies, not password-protected invite-only rooms. No random queue, persistent/networked party, eight-player game, cloud saves or account recovery is shipped. Queue/party/team contracts prepare the future four-teams-of-two mode without enabling it.

**Same-PC testing:** two copies under the same Windows account share the EOS guest identity and cannot connect to themselves. Use **LAN / THIS PC**, **HOST LAN / JOIN LAN**, address `127.0.0.1`, port `7777`. In this version, trying the EOS room instead can show the generic `EosP2PTransport` start-failure message and a `LobbyNotOwner` cleanup warning. Clearer rejection/role-aware cleanup is a known follow-up, not a fix included in this release. Use separate devices for the guest internet test.

## Steam test mode remains available

Sign into Steam and use **Start-Private-Steam-Test.cmd** (Windows) or **Start-Private-Steam-Test.command** (Mac), or enable Private Steam Test (480) at startup. This explicitly uses Valve's shared development App ID 480, not our production identity. Use separate accounts/devices, friends-only Steam lobbies, matching game builds and numeric Steam room codes. Real two-account/device Steam P2P remains unverified. Normal launch never silently adopts App ID 480.

## Checks and limitations

- 92 automated tests passed, covering prior game/network/build foundations plus EOS room-code validation, bounded packet fragmentation/reassembly/sequencing and same-pool party/queue/team reservation contracts.
- Real single-device Windows EOS login, canceled-create/late cleanup, NGO host, leave/destruction and fresh rehost passed. These are **not a two-peer relay/replication pass**. Windows LAN host/client/third-player controls/reset/rejoin, single-account Steam host/leave/rehost and normal startup/guest fallback regressions passed. Final guest menu/room captures were visually reviewed.
- Mac is a Universal Intel/Apple Silicon Mono package. Static player/Unity/Steam/EOS architecture, every ZIP file hash and executable-mode checks passed; these are separate from actual Mac launch, input, native Steam/EOS or Windows/Mac peer verification. It is **unsigned/unnotarized**; read MAC_TESTING.md. Do not disable Gatekeeper globally or force suspicious security warnings through.
- Distributed clients contain an extractable, limited EOS game-client credential, never a trusted-server/admin key. The source keeps local credentials out of Git/chat. Player-hosted matches are not a trusted ranked/reward server. No paid billing was enabled.
